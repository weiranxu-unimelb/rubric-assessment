# 实施计划：员工考核系统本地版

## 目标

按 `SPEC-employee-assessment.md` 交付可本地运行的首版：多身份登录、工号主键、组织与人员、树状指标、员工填报、管理员预审、多打分人独立评分、隔离的 Dashboard、Excel 和单机部署。

## 架构

- Next.js App Router 同时提供响应式界面和 `/api/v1` 接口。
- PostgreSQL 为唯一持久化数据库；Drizzle 管理 schema 与迁移。
- 所有状态更改在服务端校验工号身份、角色范围和版本；评分明细接口仅打分人本人或超级管理员可读。
- Excel 文件经受限解析与预校验后写入；最终结果导出在事务快照内复核完成门槛。
- 单机 Docker Compose 包含 Caddy、Web、PostgreSQL；后台任务能力优先使用数据库队列，可在导入/导出量增长时启用 Worker。

## 顺序与验收节点

1. 工程、数据库与本地启动：构建、类型检查、数据库迁移运行。
2. 登录、组织和权限：员工/管理员/超级管理员界面可切换；越权请求被拒绝。
3. 周期、指标树与打分关系：根 100 分和任意层级校验；管理员在授权范围内配置。
4. 填报与预审：员工提交、管理员逐节点退回或通过；未通过前打分人看不到任务。
5. 打分与汇总：多个打分人独立提交；最后一人提交后计算平均总分，版本冲突安全。
6. Dashboard 与 Excel：管理员只见完成进度；全部完成后仅导出总分；超级管理员见明细。
7. 移动端与部署：手机视口操作、Docker Compose、本地启动说明和关键流程测试。

## 风险

| 风险 | 处理 |
| --- | --- |
| 工号主键变更 | 初版即以工号作人员表主键及所有人员外键。 |
| 管理员意外看到分数 | 使用分离查询和响应 DTO；不从评分明细表读取管理员 Dashboard。 |
| 最后一名打分人并发提交 | 事务锁定考核单、唯一约束、版本号与幂等键。 |
| 低配 ECS 内存 | 单体 Web + PostgreSQL；限制导入文件大小和同步任务，使用 standalone 镜像。 |

## 待业务明确但不阻塞本地版的约定

- 多打分人的最终分使用算术平均。
- 管理员“全部完成后可导出”的范围按其当前授权子公司及所选周期计算。
- 本地版只使用账号密码登录；外部集成保留为后续任务。
