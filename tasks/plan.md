2. 实现确定性的系数转百分比计算；部门预设保存接口与服务端自动配置打分关系。
3. 扩展员工新增/编辑/Excel、部门预设管理与打分关系 UI。

风险：当前数据库存在进行中周期；演示员工入库须避免误改已有员工、已发布关系与评分任务。

## Overview

将同一员工在同一考核周期内多个打分人的最终得分，从等权平均改为管理员在草稿周期配置的加权平均。权重是打分关系的一部分，评分任务创建时会冻结权重快照。

## Architecture Decisions

- 权重使用 `numeric(5,2)`，范围为 `(0, 100]`；同一“周期、被打分人”的全部打分关系之和必须为 `100.00`。
- 仅允许在 `DRAFT` 周期配置打分人和权重；`ACTIVE` 后关系与权重冻结。
- 每个 `score_task` 保存创建时的权重快照，最终得分只使用该快照计算，避免以后修改关系影响历史结果。
- 旧接口中仅传工号的调用继续支持：服务端为多个打分人生成精确合计为 100 的默认均分权重。
- 同一员工的打分关系替换在一个事务中执行，并锁定考核单，避免并发写入出现部分成功或权重不一致。

## Dependency Graph

```text
数据库迁移与领域计算
  └─ 打分关系 API / 发布校验 / 评分任务快照
       ├─ 状态接口、评分结果与 Excel 导出
       └─ 管理员人员配置界面与 Excel 导入
```

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| 三人均分时两位小数无法自然合计 100 | 默认分配时将余量放入排序第一人，例如 33.34/33.33/33.33。 |
| 并发修改导致关系与权重半更新 | 在事务中锁定考核单并整体替换关系；发布阶段再次校验。 |
| 已有数据没有权重 | 迁移按每组现有打分人均分回填，单人回填 100。 |
| 历史评分口径被后续调整改变 | 评分任务创建时持久化权重快照；最终分只读快照。 |

## Task List

1. 数据库迁移、领域校验与加权计算。
2. 打分关系配置 API、草稿发布校验、评分任务快照和最终分计算。
3. 状态数据、Excel 模板/导入/导出契约。
4. 管理员人员配置 UI 的权重编辑、合计与错误提示。
5. 全量回归、真实数据库迁移验证及本地 Docker 部署。

## Acceptance Criteria

- 单打分人始终为 100% 权重，最终分与现有行为一致。
- 多人权重不等于 100 时不能保存或发布；管理员能看到具体员工和当前合计。
- 全部评分提交后，最终分为 `Σ(打分人总分 × 权重 / 100)`，仅最终结果四舍五入到两位小数。
- 管理员不可在已发布或已停止周期修改权重。
- 评分明细导出包含打分人权重、打分人总分与加权贡献；最终总分导出保持简洁。
